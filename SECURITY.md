# Security Policy

This workspace currently declares version **0.1.0** and is under development.
No supported-release security-update matrix or independent security audit is
published here. Passing tests do not constitute a security audit.

## Reporting a vulnerability

Use the repository's private vulnerability-reporting channel if it is enabled.
If it is unavailable, ask the maintainers for a private reporting channel without
publishing exploit details, private keys or wallet material in a public issue.
This repository does not currently specify a dedicated security email or response
SLA; no reporting address or response deadline should be inferred from this file.

A useful private report includes the affected revision, execution path, impact,
reproduction steps and a minimal test case with synthetic data. Keep operational
credentials and real signing material out of the report.

See the [security roadmap](docs/SECURITY_ROADMAP.md) for implemented controls and
open verification gates, and [ProgramCall compatibility](docs/PROGRAM_CALL.md#storage-and-compatibility)
for chain/storage boundaries.
