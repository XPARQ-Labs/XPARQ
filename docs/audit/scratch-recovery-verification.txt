Scratch recovery verification — 2026-10-05

Behavior
- Missing local rollback journals route sync to isolated recovery rather than
  rejecting the candidate as consensus-invalid.
- Candidate header PoW, difficulty, work and weight are independently verified.
- Restore a validated local snapshot no higher than the common ancestor, or
  replay genesis; pin prefix bodies to captured canonical headers.
- Fully execute candidate blocks before publication; stream bodies into scratch
  and retain the existing bounded body cache.
- Persist the final validated state snapshot in scratch. Publish canonical log,
  derived indexes, mempool and recovered snapshot in one redb transaction.
- Recheck active tip and fork preference under the mutation lock before commit.
- Single-flight recovery; bounded 64-entry invalid block commitment history.
  Local read failures and uncommitted/corrupt bodies do not poison that history.
- Owned scratch directories are cleaned up on normal success/error paths.
- The canonical replacement now writes the program address index version marker.

Limits
- Production journal pruning remains disabled. Snapshot journal coverage and
  historical explorer receipt lookup must be adapted before enabling it.
- Execution state and journals remain in memory; this is not a disk-backed UTXO
  implementation. Snapshot encoding can temporarily increase memory usage.
- The scratch prefix duplicates canonical bodies on disk during recovery.
- A process crash can leave an isolated scratch directory. Startup never loads
  these directories as canonical state; automatic stale-directory cleanup is
  not implemented.
- Schema version 10, snapshot version 3, consensus/block encoding, chain
  specification and wallet format are unchanged.
- No new full-workspace mainnet frozen-vector result is claimed.
