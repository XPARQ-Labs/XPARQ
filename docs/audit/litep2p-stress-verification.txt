litep2p large valid-body resource and admission verification

Scope: opt-in litep2p-devnet, real localhost TCP/Noise/Yamux, Linux /proc metrics.
Default TCP and consensus/wire identities remain unchanged.

Finding and fix:
The immediate global-slot rejection policy let four peers retaining two inbound
slots each deny a fifth peer admission before the application fair queue. The
pre-fix loaded sync did not complete during 763.707 seconds of observation. Its
baseline completed in 58.195 seconds. The loaded run was stopped before the
900-second deadline to implement transport admission waiting; it was not a
completed test or a statistically comparable performance benchmark.

The production node now selects 8 active requests, 32 additional global-slot
waiters and 2 peer slots across all phases. The active limit is enforced by owned
global semaphore permits carried through read/application/write/cleanup. Waiters
register FIFO, expire after 5 seconds, and do not read frames before admission.
Admitted reads have a separate 5-second whole-frame deadline. Total tracked
waiting/active streams are capped at 40; overflow is dropped without frame decode.
Per-peer permits also cover waiting. Reconnect does not transfer old peer permits.
The optional vendored builder defaults to zero waiters for other callers.

Large valid-body fixture:
Canonical genesis plus 66 mined blocks: one funding block and 65 signed 1 MiB
XPVM deployments. The programs are valid nop/const/return code, deployed rather
than invoked. Fees, burns and commitments use the actual ledger; ML-DSA-44 signs
payments. Every block passes apply_block before production storage persists it.
Canonical encoded bytes including genesis: 68,421,370 (65.25 MiB). Targets create
genesis locally and download the subsequent bodies over the network.

Direct transport regressions:
cargo test -p node --locked --no-default-features --features litep2p-devnet --test litep2p_limits
Result: 6 passed, 0 failed (4.95 s): 3 budget unit tests and 3 real transport tests.
The new fixture holds both global slots, queues two different peers, rejects
queue overflow and excess peer occupancy, releases one active slot, observes
FIFO admission, expires the remaining waiter without releasing either active
application slot, then verifies successful service after a real slot release.
Existing frame size, response size, slow read/write, reconnect and egress tests pass.

Limitations:
A larger group can fill the 32 waiting slots, connection table or aggregate
request/response budgets. No Sybil resistance or hard response-time guarantee
is claimed. Existing transport buffering remains separate from frame decoding.
Canonical history and deployed-program state still consume substantial RAM;
this experiment establishes neither constant RSS nor a whole-process CPU cap.
No multi-hour soak, thousands-of-block benchmark, WAN/NAT test or production-
default qualification was performed. See docs/LITEP2P_STRESS.md for reproduction.
