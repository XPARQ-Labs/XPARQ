Production journal pruning verification — 2026-10-05

Runtime behavior
- Default retention is 256 recent block journals, including the current tip.
- Kernel exposes retention metadata/primitive but does not choose the window.
- Journal deletion does not change execution state or consensus commitments.
- Archive per-operation burn receipts in auxiliary storage keyed by block hash
  before deleting undo data. Validate receipt size/count and canonical header.
- Archive failure defers pruning and preserves all journals and valid state.
- Apply retention during canonical publication, startup replay, sync and scratch
  replay. Historical bodies are not deleted.
- Snapshot restoration accepts only a complete contiguous retained suffix ending
  at its tip, with the exact journal count for each retained block.
- Stronger deep forks recover through scratch. Concurrent canonical appends may
  continue: recheck latest work and active state root before publishing. A changed
  common ancestor defers recovery and requires a new sync session.

Compatibility and limits
- Storage schema 10, snapshot encoding/version 3, block encoding, chain spec and
  wallet format unchanged. Older full-journal snapshots remain readable.
- Retention bounds journal count, not bytes/RSS. Active state/headers remain RAM.
- Loading an old full-journal snapshot can temporarily exceed the new window.
- Disk-backed historical receipt rows for discarded branches are not deleted.
  They are non-consensus caches; canonical membership is verified independently.
- No full-workspace mainnet frozen-vector pass is claimed by these devnet tests.
